# Draco 本地压缩

一个**双击就能用**的本地小工具：拖入 `.glb` → 用 Draco 重编码 → 下载。

只用本机的 Node 跑，文件不出本机、不上传任何服务器。

---

## 为什么单独做这个

浏览器里做不了 Draco 编码，这是实测结论，不是偷懒：

| 方案 | 结果 |
|---|---|
| npm 的 `draco3d` | 只有 Node 版 glue，浏览器里 `require('fs')` 直接炸 |
| three.js 自带的 `draco_encoder.js`（asm.js） | Chrome 157 里一初始化就 `Target crashed`，换 `TOTAL_MEMORY` 等参数无效 |
| 浏览器里退而求其次用 meshopt FILTER | 能用，但**不做量化**，只到 −45%（208 MB → 113 MB） |

所以「Draco 级」的压缩只能在本地跑：**208.24 MB → 63.20 MB（−69.6%）**。

---

## 怎么用

**双击 `start.cmd`**。它会：

1. 检查 Node（没有就提示去装）
2. 起一个本地服务（默认 `http://localhost:8099`，被占用会自动顺延）
3. 自动打开浏览器

然后在页面里：

4. 把 `.glb` 拖进方框（支持多选，逐个压缩）
5. 选档位（默认「均衡 14bit」）
6. 跑完点「下载」，产物同时保存在 `draco-tool/out/`

**关掉那个黑窗口就停止服务。** 也可以用 `stop.cmd` 兜底杀进程（会扫 8099–8111）。
首次使用无需 `npm install` —— 依赖复用上一级目录的 `node_modules`。

> 不要用命令行的同学可以忽略下面这段；想批量跑还是用上级目录的 `node src/cli.mjs build`。

```bash
cd draco-tool
node server.mjs               # 起服务
PORT=9000 node server.mjs     # 换端口
NO_OPEN=1 node server.mjs     # 不自动开浏览器
```

## 「已经压过的不再压」是怎么判断的

**不是看有没有 Draco 扩展。** 3ds Max 的原始导出本身就带 Draco，但用的是低压缩设置
（实测 **25.46 字节/顶点**）；重压一次能到 **4.54 B/顶点**，收益 69% —— 这正是主要用途。

真正的判据是**每顶点几何字节数**：

| 文件 | 字节/顶点 | 处理 |
|---|---|---|
| 3ds Max 原始导出（自带 Draco、低压缩） | 25.46 | ✅ 压缩（本次主要场景） |
| 浏览器 meshopt 产物（`*_opt.glb`） | ≈11.3 | ✅ 压缩（Draco 能再省一半） |
| 本工具 / Node CLI 的 Draco 产物 | 4.54 | ⛔ 拒绝（已接近极限） |

低于 **8 字节/顶点**直接拒绝并说明原因，因为量化是不可逆的：读回来的坐标已经是整型，
再用浮点编码重排必然膨胀 —— 实测 63.63 MB 的产物被浏览器"压缩"成了 **115.34 MB**。

## 压缩参数

与 `node src/cli.mjs build` 完全一致（同一份 `src/compress.mjs`）：

```
方法        edgebreaker
位置        14 bit（均衡）/ 16 bit（高保真）/ 12 bit（小体积）
法线        10 bit（小体积档 8 bit）
UV          12 bit（小体积档 10 bit）
顶点色      8 bit
编码速度    5（默认，1 最慢最小）
```

三档怎么选：

| 档位 | 误差（30 m 尺度） | 用在哪 |
|---|---|---|
| 均衡 14bit | ≈3.6 mm | 默认，建筑构件上肉眼不可见 |
| 高保真 16bit | ≈0.9 mm | 要毫米级、或下游还要二次处理 |
| 小体积 12bit | ≈14 mm | 远观总图/汇报，别用于单体交付 |

**只重编码几何**：不 weld、不 simplify、不 prune、不 join。任何拓扑改动都会破坏
BIM 构件与属性的一一对应关系。

## 压完会自动校验

每次压缩都会跑 19 项比对（`src/verify.mjs`），页面上可以展开看明细：

- 节点数 / 名称 / 父子层级逐项一致
- **extras 用户属性逐条一致**（本模型 795,727 条，一条都不能少）
- 材质定义按多重集比较（同名材质会有多份）
- 节点变换用「角点位移」判据，避免 float32 噪声误报
- 三角面数不变

顺带会修 `asset.version: "2.1"` → `"2.0"`：3ds Max 写的是非法值，不修的话
three.js / glTF-Transform 都会直接拒绝加载。

## 与浏览器版（`web/`）的分工

| | `web/`（纯前端） | `draco-tool/`（本地） |
|---|---|---|
| 压缩算法 | meshopt FILTER（不量化） | **Draco edgebreaker（量化）** |
| 实测体积 | 208 MB → 113 MB（−45.7%） | **208 MB → 63 MB（−69.6%）** |
| 依赖 | 无，纯静态，可直接部署 | 需要本机 Node 18+ |
| 适合 | 快速预览、随手压一下、部署给别人用 | 出交付文件、追求体积 |

也就是说：**先在 web 里看，定稿再用这个工具压**。

## 常见问题

**端口被占用？** 会自动顺延到 8100、8101…，以窗口里打印的地址为准；`stop.cmd` 会扫这一段。

**双击后一闪而过？** 窗口里会留一行 `Exited with code N` 和报错。多半是 Node 版本低于 18。

**大文件卡住/崩？** 208 MB 的文件编码时堆峰值约 2.5 GB，`start.cmd` 已设
`NODE_OPTIONS=--max-old-space-size=8192`。内存小于 8 GB 的机器建议一次只压一个。

**产物在哪？** `draco-tool/out/`，文件名是 `<原名>_draco.glb`（非均衡档会带档位后缀）。
